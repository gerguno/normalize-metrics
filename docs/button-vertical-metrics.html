Equal padding-block does not center ink

CSS pads the font’s line box (hhea ascent + descent on macOS), not the visible letters. The fonts that look centered keep empty space above cap-height close to empty space below the baseline. The fonts that look off pin ascent to the top of H and leave ~25–29% of the em hanging unused under the baseline.

What this number is

Cap-center offset is ((ascent − H.yMax) − |descent|) / 2, scaled to 1000 units per em. Zero means the vertical center of H sits on the center of the CSS content area. Negative means the word sits high in the button. Measured from compiled Regular faces (DIN Condensed Bold; Inter 3.3 subset). Source: local font files via fontTools, macOS hhea path.

Same button, two metric systems

Dashed line is the mathematical center of the line box. The vertical tick is how far the cap-ink center misses it. Outer fill is equal padding-block around that box — the padding is not the bug.

Why DIN looks glued to the top

hhea ascent is 712, and H’s top is also 712. Caps touch the top of the em square. Descent is −288, so almost 29% of the line box is empty cellar under a word like SAVE that has no descenders. Equal padding then wraps that cellar, so the word reads high.

Areal leaves 162 units above H and 210 below the baseline. The leftover is almost symmetric, so the same padding looks centered.

Two vendor strategies, not two quality levels

UI / display metrics

hhea ascent sits well above cap-height so umlauts, rings, and a bit of breathing room live inside the line box. Descent is sized to roughly match that leftover. Content height is often 1088–1506‰ of em — they do not force ascent + descent = UPM.

ABC Areal, ABC Camera (hhea/win), ABC Walter (hhea/win), Inter 3 hhea, Helvetica Neue, Roboto hhea, Neue Haas Unica hhea, KTF Techne (hhea ≈ typo, same leftover pattern as Areal).

Em-square / metal-type metrics

typo and hhea are packed into the em: ascent + |descent| = 1000. Ascent is set near cap-height (Univers 724 vs H 722; DIN 712 = H 712). The remaining ~280 units all go under the baseline. Accents stick out of the typo box; Win metrics are enlarged only so Windows will not clip them.

Akkurat LL, Unica77 LL, Univers LT CYR, DIN Condensed. Lineto, Linotype, and DIN-style families inherited this from metal / early PostScript practice.

Platform split

macOS Core Text uses hhea. Windows DirectWrite uses OS/2 typo metrics only if USE_TYPO_METRICS is set; otherwise Win ascent / descent. Most of these files leave that bit off, so Mac and Windows can disagree.

What CSS actually does

A button with equal padding-block centers the line box, not the ink. With line-height: normal, extra lineGap is split equally as half-leading, which does not cancel an asymmetric ascent/descent split — Univers and DIN both have lineGap 200, and they still sit 137–144‰ off.

A one-word label without descenders (Save, Next, OK) makes this obvious. The cellar reserved for p/g/y stays empty. Mixed-case copy is even more top-heavy because most of the ink only reaches x-height.

The layout spec is CSS Inline Module Level 3: the content area is the font’s ascent and descent metrics. The intended fix is now text-box: trim-both cap alphabetic (Chrome 133+, Safari 18.2+), which trims to cap-height and the alphabetic baseline so equal padding finally means equal space around the letters.

If the goal is the button, not the font

Use text-box: trim-both cap alphabetic on the label. That makes Areal and DIN behave the same under equal padding-block, without editing font files.

Do you need Glyphs MCP?

Font files are enough to explain this

CSS never sees Glyphs masters, alignment zones, or custom parameters. It sees hhea, OS/2 (sTypo*, usWin*, sCapHeight, USE_TYPO_METRICS), and the actual H outline. Those live in the installed OTF/TTF/WOFF. That is what this page measured.

Open Glyphs only if you want to change them

Glyphs MCP is useful to rewrite vertical metrics (typoAscender, hheaAscender, winAscent, corresponding descenders, lineGap) and to check that umlauts still fit. It is not required for diagnosis.

NeuzeitGroT was not measurable

/Library/Fonts/NeuzeGroTReg.ttf and its siblings are empty 0-byte files from 1996. A real Neuzeit Grotesk OTF/TTF is needed to put it on this chart. The family is a 1960s Berthold grotesque in the same metric tradition as Univers, so it is expected to land in the off group.

What I used

Inter is the Gravity Forms 3.3 subset (official Inter 3 hhea/OS/2 tables). Helvetica Neue is the Regular face inside /System/Library/Fonts/HelveticaNeue.ttc. ABC Camera is the unlicensed trial Regular. DIN is Apple’s Supplemental Bold — no Regular is installed.
